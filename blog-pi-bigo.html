Watching Big-O Happen

Computing π the slow way — and plotting the runtime as it grows, so you can see time complexity instead of just reading about it.

The Leibniz series

There’s a famously simple infinite series for π:

π = 4·(1 − 1/3 + 1/5 − 1/7 + 1/9 − …)

Summing n terms is a single loop that does a constant amount of work per term, so computing it is O(n) — linear in the number of terms. (It’s also a famously bad way to get precision: it converges painfully slowly. That’s not the point here.)

The idea: measure, don’t assume

Instead of just computing π, this project times the computation. For n from 0 up to 100,000, it runs the summation, records the wall-clock time with time.perf_counter(), and live-plots time against n on a dark Matplotlib canvas. The line you watch grow is the algorithm’s complexity drawing itself.

for i in range(0, 100000):
    terms.append(i)
    start = time.perf_counter()
    calculate_pi(i)
    end = time.perf_counter()
    times.append(end - start)
    plt.plot(terms, times, color="red")
    plt.draw(); plt.pause(0.1)

Why it’s a nice teaching tool

Big-O is usually taught as algebra on a whiteboard. Here you get the empirical version: a straight-ish line emerging from noisy real timings is exactly what O(n) looks like in practice. It also quietly teaches the caveats — timing jitter, OS scheduling, and warm-up effects mean the measured curve is never perfectly clean, which is the honest reality of benchmarking.
